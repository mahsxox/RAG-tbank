# T-Bank IFRS RAG

Вопросно-ответная система по финансовой отчётности Т-Банка (МСФО, PDF). Извлекает точные числовые значения из таблиц отчётов и формирует ответ с указанием источника (файл, страница, год отчёта).

На тестовом наборе из 15 вопросов по трём годовым отчётам система стабильно даёт **≥ 80 % попаданий нужной страницы в топ-3** и ≥ 80 % верных ответов LLM.

## Быстрый старт

Требуется Docker Desktop (Windows/macOS) или Docker Engine + Compose v2 (Linux) и ключ доступа к GigaChat API.

```bash
git clone <repo> RAG_test && cd RAG_test
cp .env.example .env            # вписать GIGACHAT_CREDENTIALS
cp /path/to/T-bank_MFSO_20*.pdf data/
docker compose up --build       # Windows: scripts\run.ps1, Linux/macOS: scripts/run.sh
```

Откройте <http://localhost:8501>. Первый запуск занимает 5–10 минут: скачиваются модели (~2.5 ГБ) и индексируются PDF. Последующие запуски — несколько секунд.

## Архитектура

```
                ┌──────────────────────────── индексация ────────────────────────────┐
PDF ──► PyMuPDF ──► очистка (колонтитулы, пробелы) ──► чанки 800 симв. по строкам ──►
     ──► [dense: multilingual-e5-small] + [sparse: BM25 ru-stemmer] ──► Qdrant (named vectors, payload)

                ┌──────────────────────────── запрос ────────────────────────────────┐
вопрос ──► год ──► payload-фильтр report_year
       ──► dense top-25 ∪ BM25 top-15 ──► cross-encoder bge-reranker-v2-m3 ──► top-8 чанков
       ──► уникальные страницы (parent-document) ──► контекст с заголовками ──► GigaChat ──► ответ + источники
```

Ключевые решения:

| Проблема данных | Решение |
|---|---|
| Колонтитул на каждой странице забивает BM25 | Автоматическое удаление строк, встречающихся на ≥ 30 % страниц файла |
| Год в вопросе совпадает со всеми страницами отчёта | Год — фильтр по метаданным, а не поисковый термин |
| PyMuPDF рвёт таблицы пустыми строками, строка «ИТОГО АКТИВЫ» становилась чанком из двух слов | Нарезка по строкам, схлопывание пробелов; чанк = 15–20 строк таблицы |
| Чанк из середины таблицы — «числа без контекста» | Префикс с годом отчёта и заголовком страницы в индексируемом тексте и в тексте для reranker'а |
| Нужное число в соседнем чанке той же таблицы | В LLM уходит целая страница, поиск — по чанкам |
| Bi-encoder не различает «прибыль за год» и «прибыль до налогообложения» | Cross-encoder reranker поверх объединения веток |

## Установка и запуск

### Вариант A — Docker (рекомендуется)

```bash
cp .env.example .env
# .env:
#   GIGACHAT_CREDENTIALS=<authorization key из личного кабинета>
#   GIGACHAT_SCOPE=GIGACHAT_API_PERS

docker compose up --build -d
docker compose logs -f app            # дождаться "You can now view your Streamlit app"
```

Что происходит при старте контейнера `app`:

1. ожидание готовности Qdrant;
2. если в `data/` есть PDF и коллекция пуста — индексация (`populate_db.py`);
3. запуск Streamlit на порту 8501.

Полезные команды:

```bash
docker compose exec app python db_scripts/verify_retrieval.py --quick     # тест retrieval
docker compose exec app python db_scripts/populate_db.py --recreate        # полная переиндексация
docker compose run --rm app verify --llm                                   # тест со сквозным прогоном LLM
docker compose down                                                        # остановить (данные и модели сохраняются в volumes)
docker compose down -v                                                     # остановить и удалить индекс и кэш моделей
```

Отключить автоиндексацию при старте: `AUTO_INDEX=0` в `environment` сервиса `app`.

## Веб-интерфейс

<http://localhost:8501>

**Основная область** — чат. Каждый ответ сопровождается раскрывающимся блоком «Источники»: страницы отчётов, ушедшие в контекст LLM, с файлом, номером страницы, годом отчёта и score reranker'а.

**Боковая панель:**

- параметры индекса: коллекция, эмбеддер, reranker, число чанков;
- список проиндексированных файлов (страниц, чанков, год) с кнопкой удаления из индекса;
- загрузка новых PDF (несколько файлов за раз) с немедленной индексацией;
- кнопка индексации файлов, лежащих в `data/`, но отсутствующих в индексе;
- ползунок числа чанков после reranker'а.

## Управление базой документов

### Через интерфейс

1. Боковая панель → «Добавить файлы» → выбрать PDF → «Загрузить и проиндексировать».
2. Файл сохраняется в `data/` и индексируется. Если файл с таким именем уже есть в индексе, старые записи удаляются и заменяются.
3. Удаление — кнопка ✕ рядом с файлом (удаляет из индекса; файл в `data/` остаётся).

### Через командную строку

```bash
python db_scripts/populate_db.py              # проиндексировать data/, если коллекция пуста
python db_scripts/populate_db.py --recreate   # удалить коллекцию и проиндексировать заново
```

### Правила именования файлов

Год отчёта определяется из имени файла — первое четырёхзначное число вида `20xx`: `T-bank_MFSO_2024.pdf` → `report_year=2024`. Год используется для фильтрации: вопрос про 2024 год ищет в отчётах за 2024 и 2025 (в отчёте за 2025 данные 2024 есть как сравнительные). Файл без года в имени индексируется, но не участвует в фильтрации по году — `populate_db` выведет предупреждение.

### Смена эмбеддера

Имя коллекции содержит slug модели (`tbank_ifrs__intfloat_multilingual_e5_small__v2`), а размерность векторов берётся из модели. Смена `EMBEDDING_MODEL` создаёт новую коллекцию, старая не затрагивается. После смены — `populate_db.py`.

## Тестирование качества retrieval

```bash
python db_scripts/verify_retrieval.py            # все вопросы
python db_scripts/verify_retrieval.py --quick    # только зачётные
python db_scripts/verify_retrieval.py --llm      # + ответ GigaChat на каждый вопрос
```

Набор: 15 зачётных вопросов по отчётам 2023–2025 (баланс, ОПУ, совокупный доход) с эталонными числами, сверенными с PDF, плюс 2 диагностических вне зачёта (неоднозначная формулировка; термин, которого нет в отчёте).

Метрика: после reranker'а `TOP_K` чанков схлопываются в уникальные страницы; вопрос засчитан, если страница с эталонным числом стоит на позиции ≤ 3. Цель — 80 %.

Пример строки вывода:

```
Q: Сколько активов у банка на 31 декабря 2024?
   candidates=38  retrieval 0.05s  rerank 9.8s
   expected=3 791 332   chunk d/s/f=None/None/None   page d/s=3/7   page@final=1  -> HIT
```

| Столбец | Смысл |
|---|---|
| `chunk d/s/f` | ранг чанка с числом в dense-ветке / BM25 / после reranker'а |
| `page d/s` | ранг страницы с числом в ветках (любой её чанк) |
| `page@final` | ранг страницы среди уникальных страниц TOP_K — критерий |

Здесь чанк с «ИТОГО АКТИВЫ» не найден ни одной веткой (в нём нет слов из вопроса), но страница баланса найдена по соседнему чанку и отдана LLM целиком — ответ верный.

Добавить свои вопросы: список `TARGETS` в `verify_retrieval.py`, формат `(вопрос, "эталонное число", зачётный: bool)`.

Отладка одного запроса:

```bash
python db_scripts/test_search.py "чистая прибыль 2024"
python db_scripts/test_search.py "чистая прибыль 2024" --no-rerank    # что даёт RRF без reranker'а
```

## Как это работает: детали пайплайна

### Индексация (`loader.py`, `vector_store.add_documents`)

1. **Извлечение текста.** PyMuPDF, `get_text("text", sort=True)` — порядок строк таблиц слева направо, сверху вниз. Пробелы, которыми выровнены колонки, схлопываются; пустые строки удаляются. Полный текст страницы сохраняется в `metadata.page_text`.
2. **Нарезка.** `RecursiveCharacterTextSplitter` с разделителями `["\n", " ", ""]` — только по строкам, чанки заполняются подряд идущими строками до 800 символов. Абзацный разделитель `\n\n` не используется намеренно.
3. **Колонтитулы.** Для каждого файла считается, на какой доле страниц встречается каждая строка длиннее 20 символов. Строки с долей ≥ 30 % удаляются из всех чанков и из `page_text`.
4. **Заголовок страницы.** Первая содержательная строка первого чанка страницы («Раскрываемый консолидированный отчёт о финансовом положении…», «12 Средства других банков»).
5. **Представления чанка:**
   - `text` — очищенный чанк, исходное форматирование чисел («55 262»);
   - для dense: `passage: Отчёт МСФО за 2024 год. <заголовок страницы>\n<text>`;
   - для BM25: `<заголовок>\n<text>` с нормализованными числами («55262»), чтобы число было одним токеном;
   - `page_text` — вся страница без колонтитулов.
6. **Qdrant.** Named vectors: `dense` (cosine, размерность из модели) и `bm25` (sparse, `Modifier.IDF` — IDF считает сервер). Payload: `text`, `page_text`, `file`, `page`, `page_title`, `report_year`. Индексы payload по `report_year`, `source`, `file`. ID точки детерминированный (uuid5 от файла, страницы, номера чанка и хэша текста) — повторная индексация идемпотентна.

### Поиск (`vector_store.retrieve_candidates`, `search_similar`)

1. **Год.** Из вопроса извлекаются четырёхзначные годы; фильтр `report_year ∈ {Y, Y+1}` для каждого найденного года. Если фильтр даёт меньше `TOP_K` результатов — повтор без фильтра.
2. **Две ветки.** Dense top-25 и BM25 top-15 с тем же фильтром.
3. **Объединение.** Без промежуточного ранжирования — reranker получает всё, что нашла хотя бы одна ветка. (RRF-слияние на стороне Qdrant используется только в режиме без reranker'а.)
4. **Reranker.** `bge-reranker-v2-m3` оценивает пары (вопрос, `Отчёт МСФО за <год> год.\n<заголовок страницы>\n<чанк>`) → `TOP_K` чанков.

### Генерация (`rag_pipeline.py`)

1. Чанки схлопываются до уникальных страниц в порядке появления, берутся первые `CONTEXT_PAGES`.
2. Каждая страница в контексте предваряется `[i] Отчёт МСФО за 2024 год, файл T-bank_MFSO_2024.pdf, стр. 7` — так LLM понимает, к какому году относится первая колонка таблицы, даже если шапка таблицы на другой странице.
3. GigaChat, `temperature=0`. Ответ возвращается с массивом `sources`.

## Диагностика и типовые проблемы

| Симптом | Причина / действие |
|---|---|
| `GIGACHAT_CREDENTIALS не найдена … существует: False` | Файл `.env` не в корне проекта или называется `.env.txt`. Проверка: `Get-ChildItem -Force -Filter ".env*"` |
| `404 No such model` | `GIGACHAT_MODEL` не из списка доступных ключу; см. команду в разделе «Проверка ключа» |
| `RuntimeError: Коллекция … имеет dense dim=…` | Сменили эмбеддер с той же `INDEX_VERSION` на существующую коллекцию — не должно происходить; `populate_db.py --recreate` |
| `populate_db` пишет `WARNING … год отчёта` | В имени файла нет `20xx` → фильтр по году для него не работает |
| `page d/s=None/None` в verify | Страница не найдена первой стадией: проверить чанки (`test_search --no-rerank`), порог колонтитулов |
| `page d=5, page@final=None` | Найдена, но reranker вытеснил: поднять `TOP_K`, проверить формулировку вопроса |
| rerank > 20 с | Включить `RERANKER_QUANTIZE=1` (по умолчанию включено); уменьшить `DENSE_CANDIDATES`; альтернатива `RERANKER_MODEL=cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` |
| Ошибка квантизации на нестандартном CPU | `RERANKER_QUANTIZE=0` — качество не меняется |
| Предупреждение о версиях qdrant-client / сервера | Подавлено `check_compatibility=False`; Query API совместим начиная с сервера 1.10 |
| Старая коллекция `my_documents` | `python -c "from src.vector_store import delete_legacy_collection as d; d()"` |

## Ограничения

- Вопросы, использующие термины, которых нет в отчёте («выручка» у банка), находят ближайший по смыслу текст, но не число — это свойство данных, а не системы.
- Неоднозначные формулировки («стоимость активов» — баланс или справедливая стоимость?) отдаются на усмотрение reranker'а.
- Сравнение показателей из двух разных отчётов требует, чтобы обе страницы попали в `CONTEXT_PAGES`.
- Reranker на CPU — узкое место по латентности; на GPU (`RERANKER_DEVICE="cuda"`) — < 1 с.
- Отсканированные PDF без текстового слоя не поддерживаются (нужен OCR до индексации).
